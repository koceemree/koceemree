### 🧪 How I automate

**📱 Mobile — Java · Appium · Cucumber · Maven · Allure**

- **Page Object Model**: screens and locators live apart from test logic, so UI changes are fixed in one place
- **BDD with Gherkin**: scenarios are written as readable feature files and bound to step definitions
- **Tag-based runs**: suites are selected by tag (module, smoke, regression) on real devices and simulators
- **Allure reporting**: each run produces step-level reports with screenshots

**🌐 Web — TypeScript · Playwright**

- End-to-end tests with Playwright's auto-waiting and resilient locators
- Test cases derived from acceptance criteria, then executed in the browser

**🤖 AI-assisted testing — Agent skills · MCP**

- **Jira task → test cases**: an agent reads the task and the related code diff, then proposes UI test cases
- **Device exploration over MCP**: the agent drives a real device or simulator (Appium MCP, Argent) to explore and verify flows
- **Gap analysis**: the agent reviews a module, finds missing scenarios, and adds them following the repo's rules
- **Human in the loop**: findings and generated cases are reviewed before anything is posted or merged
